# Diagram tools

Two separate tools, two separate jobs. Neither touches the manuscript
pipeline itself — they're not in `vendors.lock`, don't produce book content
under `passport.yaml`'s reproducibility contract, and aren't required to run
any of the three skills.

## The README diagram — hand-authored animated SVG

**File:** [`docs/diagrams/aimprenta-pipeline-animated.svg`](diagrams/aimprenta-pipeline-animated.svg),
embedded at the top of `README.md`.

It's plain SVG with CSS `@keyframes` (dashed edges flowing) and one SMIL
`<animateMotion>` (a marker riding the full route from `Idea` to
`Interior + EPUB`) — no JavaScript, so it plays inline wherever an `<img>` or
markdown image renders an SVG, GitHub included. `prefers-reduced-motion` is
respected via a media query that turns every animation off.

It's hand-authored, not generated by archify (see below) — archify's own
animation depends on ~186KB of viewer JS/CSS that doesn't survive being
flattened into a portable file (confirmed: extracting archify's `<svg>…</svg>`
block renders as an unstyled XML tree, since its styling lives in the parent
HTML's `<style>`, not inside the SVG). To update the README diagram, edit the
SVG directly — lanes are `<rect class="lane-band …">`, nodes are
`<rect class="node-box …">` + text, edges are `<path>` in the `.edge-flow`
group, and the traveling marker's route is the `path=` attribute on
`<animateMotion>`. Validate with `python3 -c "import xml.dom.minidom as m; m.parse('file.svg')"`
and preview by serving the file locally (`python3 -m http.server`) and
opening it in a real browser — don't trust a raw file:// open or an
ImageMagick rasterization; both handle embedded SVG fonts/CSS differently
than a real renderer.

## The paper and article diagrams — hand-authored static SVG

**Files:** [`docs/diagrams/aimprenta-paper-pipeline.svg`](diagrams/aimprenta-paper-pipeline.svg)
and [`docs/diagrams/aimprenta-article-pipeline.svg`](diagrams/aimprenta-article-pipeline.svg),
embedded under README.md's "Papers and short-form articles" section.

Same hand-authored approach and palette as the book diagram above (lanes,
node boxes, the same teal/rust/red/blue color system), but plain static
SVG — no `@keyframes`, no `<animateMotion>`. The book diagram earned its
animation because it's the page's hero image; these two are secondary
illustrations of lighter pipelines, so the extra build/verification cost of
animating them wasn't worth it. Edges use a plain SVG `<marker>` arrowhead
instead of the book diagram's hand-computed triangle polygons — simpler to
maintain, and safe here since these are standalone `.svg` files loaded via
`<img>`/markdown image syntax, not inline HTML.

**A routing bug worth knowing about if you edit these:** an edge's
right-angle path can visually appear to connect to the wrong node if an
intermediate waypoint's coordinates happen to fall inside a *different*
node's box along the way — the line reads as "connects to that box" even
where the box's opaque fill later hides the overlapping segment, because
node boxes are drawn after edges. This happened once in
`aimprenta-paper-pipeline.svg` (a gate-to-gate false connection) and once in
`aimprenta-article-pipeline.svg` (draft-to-editorial passing through the
gate box) while building these — both fixed by routing the intermediate
waypoint through empty space between lane bands instead of through another
node's column. Always preview a routing change in a real browser
(`python3 -m http.server`, not a raw `file://` open) before trusting it.

## archify — optional, for local interactive exploration

**Job:** an *interactive*, explorable version of the same pipeline map — real
trace animation, dark/light toggle, and guided views you click through. Not
what's embedded in the README (see above); open it locally when you want to
explore rather than just look.

`docs/diagrams/aimprenta-pipeline.{workflow.json,html}` is the working
example: generated from a typed JSON spec and validated against archify's own
layout checker before delivery.

- Install: `npx skills add tt-a1i/archify -g`
- Author a `<type>.json` (`workflow` fits a pipeline like this one best —
  see `docs/diagrams/aimprenta-pipeline.workflow.json` for a validated example),
  then:
  ```bash
  node ~/.claude/skills/archify/bin/archify.mjs validate workflow spec.json --quality showcase --json
  node ~/.claude/skills/archify/bin/archify.mjs deliver  workflow spec.json output.html --quality showcase
  ```
- Hard layout constraint worth knowing before authoring: workflow columns
  are capped at 6 (`col` 0–5). Compress the story into ≤12 nodes rather than
  fighting the validator — `aimprenta-pipeline.workflow.json` collapses each
  editorial-QA sub-phase into one node with a `tag` for the count, and
  carries the deeper narrative in `cards` instead of extra nodes.

## diagram-design — in-book conceptual figures

**Job:** conceptual figures *inside* a book chapter — an architecture map, a
flowchart of an algorithm's stages, anything with no computed data behind it.

**Not for:** any figure that plots real computed values — loss curves,
decision boundaries, a scatter of actual data. Those stay in matplotlib,
generated by the chapter's own `code/chNN/` module per
`notebook-paired-with-prose`'s rule (every printed number traces to executed
code, pinned by a test). Handing a data-driven figure to a templated diagram
tool would break that guarantee — this split is deliberate, not an oversight.

- Install (Claude Code): `claude plugin marketplace add cathrynlavery/diagram-design`
  then `claude plugin install diagram-design@diagram-design`
- 39 layout types (architecture, flowchart, sequence, loop/flywheel, tree,
  timeline, and more), static HTML+SVG, no build step, matches a brand
  palette from a URL in ~60 seconds if you want that.
- Example use in this pipeline: `fig-ch01-cinco-casillas.png` in
  *Fundamentos de Machine Learning* — "the five pieces every algorithm
  decomposes into" — is exactly a conceptual flow diagram with zero data
  behind it, currently hand-drawn with matplotlib. That's the shape of
  figure that belongs in `diagram-design` going forward.
